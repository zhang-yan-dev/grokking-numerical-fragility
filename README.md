# Grokking 复现：极小 Transformer 上的数值敏感性研究

对 arXiv:2607.05104 *Grokking Is Conditional and Fragile: A Fully-Tractable, Multi-Seed Study at 12K Parameters* 的独立复现与一项扩展分析。

在一台笔记本上，独立重训 300 个随机种子，复现了原论文"grokking 站在数值刀刃上"的核心主张；补上一项原论文未做的量化分析，说明翻转究竟发生在哪里；并做受控重复实验，纠正了自己早期一个错误的分类判断。

---

## 1. 摘要

原论文的主张是：在 11,856 参数的 Llama 架构模型上，模运算任务的 grokking 不是一个关于随机种子的稳定性质，而是**以多种子比率衡量的条件性相变**，且其证据必须在固定的数值环境中取得 —— 换一台机器，少数种子的 grok 判定会翻转。

本项目做四件事：

1. **独立复现**（原论文结论 3）：在 `wd=0.01, threads=4` 配置下独立重训 300 个种子，与作者公开的 per-seed 记录逐种子配对。McNemar 精确检验 `p = 0.4011`，聚合 grok 率无显著差异（27.0% vs 24.7%，置信区间重叠）。**原论文的说法被独立复现。**

2. **扩展分析**（原论文未做）：把每个种子的翻转情况，按其 `best` 留出准确率到判定阈值 `τ = 0.70` 的距离分组。结果是翻转高度集中在阈值附近：`±0.10` 以内翻转率 **39.6%**（n=53），更远处 **12.1%**（n=247），比值 **3.3×**，置信区间不重叠。

3. **独立验证倒 U 型**（原论文结论 2）：补做 30 次独立训练，覆盖 `wd ∈ {0.0, 0.1, 1.0}` × 10 种子。倒 U **形状复现**（10% → 100% → 0%，作者为 20% → 90% → 0%），数值不逐字吻合 —— 两个边界配置各翻转 1 个种子。

4. **受控重复实验**（方法学校验）：对关键种子做串行 / 并行 / 重负载三种条件下的重复运行，确认 `best` 的可复现性，并据此纠正了本项目早期一个错误的分类判断（详见第 3.5 节）。

**核心机制表述**（可迁移到任何阈值化评测系统）：

> 一个种子是否翻转，由「数值噪声尺度 ÷ 到阈值的距离」决定。
> 噪声尺度 ≈ `best` 的平均跨机器绝对差 = **0.164**。
> 二元结论看起来"稳"，可能只是因为大部分样本离阈值够远 —— 而不是因为评测系统本身稳定。

`wd=1.0` 的一组（10 个种子逐位相同、零翻转）是这个机制的**正面证据**；
第 3.5 节的受控实验则划出了它的**边界**。

## 3. 结果

### 3.1 结论 3：聚合比率无检测差异（独立重训，n=300）

配置 `wd = 0.01, threads = 4`，种子 0–299，与作者公开记录一一配对。

**2×2 配对表**

|  | 本机 grok | 本机 no grok |
|---|---:|---:|
| **作者 grok** | 52 | 29 |
| **作者 no grok** | 22 | 197 |

**统计**

```
grok 率   作者  27.0%  (81/300)   95% CI [22.3%, 32.3%]
          本机  24.7%  (74/300)   95% CI [20.1%, 29.8%]
          差值  -2.3%（-7 个种子），置信区间重叠

McNemar 精确检验   p = 0.4011   → 不显著
grok 判定翻转      51/300 = 17%，且对称（29 vs 22，无系统偏差）

best 准确率完全相同   37/300 = 12.3%
best 平均绝对差       0.164
best 最大绝对差       0.750
best 均值             作者 0.439  vs  本机 0.432   （仅差 0.007）
```

**结论**：跨机器的数值环境差异会翻转少数种子的 grok 判定（17%），但不改变聚合比率。这正是原论文的论点。

### 3.2 扩展：翻转发生在哪里

按作者 `best` 到 `τ = 0.70` 的距离分组：

| 作者 best 区间 | n | 翻转率 |
|---|---:|---:|
| [0.0, 0.1) | 15 | 0% |
| [0.1, 0.2) | 45 | 4% |
| [0.2, 0.3) | 77 | 10% |
| [0.3, 0.4) | 10 | 20% |
| [0.4, 0.5) | 29 | 17% |
| [0.5, 0.6) | 36 | 11% |
| **[0.6, 0.7)** | 23 | **48%** |
| [0.7, 0.8) | 18 | 33% |
| [0.8, 0.9) | 24 | 38% |
| [0.9, 1.0) | 23 | 17% |

```
距 τ 在 ±0.10 以内    n=53    翻转率 39.6%   95% CI [28%, 53%]
距 τ 更远             n=247   翻转率 12.1%   95% CI [9%, 17%]
比值                  3.3×   （置信区间不重叠）
```

核心图：`flip_vs_threshold.png` / `.pdf`（双面板：翻转率 vs 准确率 + 配对散点）。

### 3.3 结论 2：权重衰减的倒 U 型

原论文报告 grok 率随权重衰减呈倒 U 型：`20% → 90% → 0%`（wd = 0.0 / 0.1 / 1.0）。

**本项目的验证分两层：**

- **分析层复算**（用作者代码跑作者数据，640 条记录）：得到 `20% → 90% → 0%`，**逐字吻合**。
  ⚠️ 这属于**复算**不是**复现** —— 只能说明代码与论文自洽，不构成独立证据。
- **独立重训**（本机训练，30 次）：得到 `10% → 100% → 0%`。**形状复现（倒 U），数值不逐字吻合。** 详见第 3.4 节。

### 3.4 独立重训的 wd 网格

`wd ∈ {0.0, 0.1, 1.0}` × 种子 0–9，本机独立训练（30 次训练），逐种子与作者记录配对。

| wd | 作者 grok 率 | 本机 grok 率 | 配对翻转 | best 平均绝对差 |
|---|---:|---:|---|---:|
| 0.0 | 20% (2/10) | 10% (1/10) | s9 | 0.135 |
| 0.1 | 90% (9/10) | **100% (10/10)** | s3 | 0.130 |
| 1.0 | 0% (0/10) | 0% (0/10) | 无 | **0.000** |

**倒 U 型的形状在两个独立来源上都成立**（中间高、两端低）。这是结论 2 的独立证据 —— 此前它只在分析层验证过。

**但数值并非逐字吻合，两点必须如实说明：**

**（1）两个边界配置各翻转 1 个种子，合计 2/30 ≈ 7%**，与 `n=300` 大网格的 17% 同量级。说明跨机器翻转率是稳定的，但具体哪个种子翻不可控。

- `wd=0.1` 的 s3：作者 `best = 0.45`（不 grok）→ 本机 `best = 0.80`（grok）
- `wd=0.0` 的 s9：作者 `best = 0.85`（grok）→ 本机 `best = 0.55`（不 grok）

**（2）`wd=1.0` 的 `best` 平均绝对差为 0.000 —— 10 个种子逐位相同，零翻转。** 这是 3.2 节机制的**完美正例**：wd 过大，模型学不动，`best` 全部卡在 0–5%，离阈值 0.70 极远，任何数值噪声都撼动不了判定。**"稳定"不是因为数值环境好，只是因为离阈值够远。**

### 3.5 同机重跑的可复现性（受控实验）

3.4 节里 `wd=0.1` 的 s3 是本项目最陡的一次翻转（作者 0.45 → 本机 0.80，跨幅 0.35，是平均绝对差 0.130 的 2.7 倍）。为判断它是否属于**另一类**现象（如优化轨迹分岔），做了受控重复实验：

| 条件 | s3 的 `best` | 备注 |
|---|---|---|
| 串行、空闲，重复 5 次 | **0.80 × 5** | `grok_ep = 1000` 全部相同，range = 0.0 |
| 4 路并行 | 0.80 | |
| 串行对照（空闲） | 0.80 | |
| **12 个 CPU 燃烧进程 + 训练** | **0.80** | 与空闲（0.80）完全相同，delta = 0.0 |
| 一次异常运行（同机同时有大量文件读写） | 0.85 | **唯一异常值** |

另对 8 个种子（`wd=0.0` 的 s0/s6/s9，`wd=0.1` 的 s0/s1/s3/s5/s9）做串行复核：**8/8 与存储值完全吻合**。

**三条结论：**

1. **`best` 对线程数与 CPU 竞争是稳健的。** 串行、4 路并行、12 个燃烧进程三种条件下，`best` 均为 0.80、`grok_ep` 均为 1000。这**支持**交接文档 7.4 节的判断：并发影响耗时，不影响结果。

2. **`best` 在同等条件下完全可复现**（5 次重复 range = 0.0），因此 3.4 节那个 0.85 的异常值**不能归因于线程数或 CPU 竞争**，只能归因于该次运行期间机器上发生了未记录的 I/O 争斗或调度抖动。

3. **因此 s3 的更可能解释是「同一噪声机制在极端条件下的放大」，而不是独立的第二类现象。** 它离阈值 0.25，远超 0.164 的噪声尺度，说明单次观测的波动幅度可以显著超出平均噪声尺度 —— 这本身就削弱了 3.2 节"噪声 ÷ 阈值距离"作为**预测**公式的强度，但不影响它作为**描述**的价值。

> **方法学教训（值得写进任何复现报告）**：不要用**单次**观测给现象分类。
> 本项目最初把 s3 归为"轨迹分岔"，是靠受控重复实验才纠正过来的。
> 跨机器对比本身就有噪声，若再叠加同机抖动，单次对比得出的"类别"很可能是伪影。

## 5. 局限（诚实说明）

1. **不是新论文。** 这是一次扎实的独立复现 + 一项小扩展，不足以单独发表。
2. **主要结论只覆盖一个配置。** n=300 仅针对 `wd=0.01, threads=4`；wd 网格只有 n=10（每组 10 个种子，95% CI 宽度约 ±30 个百分点）。
3. **`±0.10` 这个分界是预先选定的**，不是从数据推出来的。数据支持的抬高区间实为 0.6–0.9，与噪声尺度 0.164 吻合，但读者应知悉该阈值是人为选择。
4. **结果是支持原论文，不是推翻。** 它验证并量化了原论文的方法论主张。
5. **3.2 节的机制是描述性的，不是预测性的。** 第 3.5 节记录了一次波动幅度显著超出平均噪声尺度的单次观测（0.80 → 0.85）。这说明用 0.164 作为尺度无法预测个例，只能描述总体分布。
6. **同机抖动的来源未确定。** 已排除线程数与 CPU 竞争（受控实验），但无法进一步定位那次 0.85 的成因 —— 未记录机器状态是其根本原因。
7. **`secs` 作为来源指纹是启发式的。** 本机运行约 55–95 秒，作者并发实测约 2000 秒，用 `< 200 秒` 判定来源在两者间有很大余量，但这不是加密意义上的确证。**`secs` 不可用于性能对比**（存储值普遍比串行复核高 3–26 秒，因写入时有其他任务在跑）。
8. **无导师指导。** 全部结论未经第三方审核，反馈渠道仅有开源社区。
